[요구사항]

1. 서비스와 사용자 경험

- 수업 예제인 발표 훈련 서비스를 사용하지 않고, 본인이 기획한 서비스 주제로 제작합니다.

- 서비스의 주요 사용자, 목적, 사용자가 수행할 주요 행동을 정의합니다.

- 화면의 정보와 기능을 사용자의 목적과 주요 행동을 중심으로 구성합니다.

2. 중간고사에서 새로 구현할 기능

- 7주차에 만든 주요 사용자 흐름에 이어지는 새로운 행동이나 사용 경로 한 가지를 정하고, 브라우저에서 조작할 수 있게 구현합니다.

- 사용자의 행동에 따라 화면의 내용이나 상태가 달라져야 합니다.

- 이벤트를 연결하고 필요한 조건을 검사하여 그 결과를 화면에 보여 줍니다.

- 새 행동을 7주차 흐름의 앞·중간·끝 중 적절한 지점과 연결합니다.

- 7주차에 이미 만든 선택에 따른 항목 표시, 입력 오류 안내, 확인·수정·다시 설정만 반복하면 새 기능으로 인정하지 않습니다.

3. 입력·상태·피드백

- 새 행동에 필요한 입력이나 선택을 구분하고, 사용자가 지금 무엇을 해야 하는지 레이블과 버튼 문구로 안내합니다.

- 입력이 필요한 기능은 값이 비었거나 조건에 맞지 않을 때 무엇을 어떻게 고칠지 안내하여 과업을 계속할 수 있게 합니다.

- 입력이 없는 기능은 결과 없음·취소 등 해당 기능의 다른 상태를 안내하고 다음 행동을 제공해도 됩니다.

- 선택하거나 입력한 값이 다음 화면이나 결과에 반영되는지 확인합니다.

- 이전 단계로 돌아가는 경로가 있다면 값을 유지하고, 다시 시작하는 경로가 있다면 해당 흐름의 상태를 초기화합니다.

4. 코드와 화면

- 기존 index.html, style.css, script.js를 이어서 수정합니다.

- HTML은 구조, CSS는 상태 표현과 반응형 배치, JavaScript는 이벤트·조건·화면 갱신을 담당하도록 작성합니다.

- 데스크톱과 모바일 화면에서 새 기능을 읽고 조작할 수 있어야 합니다.

- 버튼과 입력창이 화면 밖으로 밀리거나 서로 겹치지 않는지 확인합니다.

- 완성된 서비스를 만들 필요는 없습니다. 브라우저에서 조작하며 결과를 확인할 수 있는 중간 프로토타입이면 됩니다.

5. README.md와 테스트 기록

README.md에 다음 내용을 기록합니다.

- 7주차 결과물에서 새로 추가한 기능 - 학교정보에 대한 의견 작성 창 추가

- 새 기능의 사용자 행동, 확인할 조건, 성공 반응, 오류·결과 없음·취소 등 다른 분기의 반응, 다음 행동을 적습니다.
사용자는 게시판에 기본적인 의견 예시글을 통해 어떤 의견을 적는 창구인지 알 수 있으며, 적고자 하는 내용을 텍스트로 입력하여 저장할 수 있다.
게시판에 의견이 등록되는 즉시 아래의 의견 게시판에 새로운 의견이 등록된다.
사용자는 등록된 게시판에 공감 표시를 할 수 있다.
사용자는 새 의견을 추가하고 싶을 시, 의견 더 작성하기 텍스트를 클릭하여 의견 작성 창구로 올라갈 수 있다.
